## 공개 저장소 준비 중 추가 확인

개인 키 파일을 제외한 복사본에서 전체 검사를 실행해, `private_config.py`가 없을 때 환경 변수로 넘어가지 못하는 오류를 재현했다. 상대 import 대신 모듈을 명시적으로 불러오고, 해당 파일 부재만 처리하도록 수정했다. 파일 내부의 다른 의존성 오류는 숨기지 않는다.

환경 변수만 있는 경우, 로컬 값 우선·빈 값의 환경 변수 대체, 다른 의존성 오류 전파를 검사하는 3개 회귀 검사를 추가했다. 기존 제공자 검사도 실제 개인 파일 대신 메모리의 빈 시험 모듈을 사용하도록 정리했다. 공개용 소스에서 PC Python 144개와 JavaScript 61개가 통과했다. 파이의 기존 배포본과 역사적 ZIP은 그대로 보관하며 이 추가 수정을 파이에 새로 배포한 것은 아니다.

## 자동 검사

최종 Python 검사는 PC와 파이에서 각각 141개, JavaScript 검사는 PC에서 61개 통과했다. 검사 대상에는 새 촬영, 캐시 배제, 취소와 중복 요청, 관찰 제한, 입력 필터, 화면 상태와 음량 제어가 포함된다. 검사 개수는 인식 정확도나 사용자 만족도를 나타내지 않는다.

사진 갱신 관련 회귀 검사는 다음 문제를 다룬다.

- 새 사진 요청과 부정·과거 사진 질문을 구분한다.
- `capture_request(flush=True)`를 사용하고 요청을 반환한다.
- 배경 관찰이 꺼져 있어도 명시적 촬영은 가능하며 관찰을 강제로 켜지 않는다.
- 새 사진 분석에 업로드 자료와 이전 관찰 캐시를 넣지 않는다.
- 촬영 실패와 취소 후 과거 사진으로 답하지 않는다.
- 마이크 상태 갱신과 자막 순서가 경합해도 촬영이 누락되지 않는다.
- 같은 요청의 중복 위임을 한 번의 노출로 합친다.

## 실제 API와 파이 확인

10월 22일 PC Chrome → SSH 터널 → 파이 서버 → Live/Noeul 및 별도 분석 AI 경로를 확인했다. 실제 마이크 대신 고정 합성 문장을 사용한 시험이다.

합성 인사는 노을 음성 응답을 받았다. 합성 카메라 질문은 전체 입력 인식, 분석 위임, 실제 주변 장면에 대한 음성 설명을 확인했다. 렌즈 방향을 바꾸기 전에는 흐린 프레임이 들어왔고, 사용자가 조정한 뒤 사물이 구분되는 장면이 수신되었다.

## 실제 장치와 모의 검사를 구분하기

LCD·터치·USB 입출력은 사용자 확인과 실제 장치 상태 확인을 거쳤다. 음량 설정은 브라우저에서 값을 바꾼 뒤 파이 출력값으로 반영 여부를 확인했다. 화면의 800×480 배치도 검사했다.

입력 필터의 작은 배경음·짧은 충격·선행 버퍼·약한 후속 음절 유지 등은 합성 PCM 및 브라우저 시험으로 확인했다. 이는 실제 내 목소리와 타인의 목소리를 구별하는 성능 시험이 아니다.

프로액티브 안내의 조용한 틈, 세션·장면 유효성, 예산·횟수·만료 조건은 모의 검사했다. 실제 생활에서 안내가 적절하고 유용한지, 장시간 사용해도 방해가 없는지는 추가 확인이 필요하다.
